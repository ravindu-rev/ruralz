# Ruralz agent instructions

Ruralz is an Apache-2.0 API gateway in Go with no feature gating, owned by Revington. Module `github.com/ravindu-rev/ruralz`. `docs/` is the spec. The code is at milestone M1 Core gateway, in progress: `ruralzd` serves file-mode traffic, and release `0.1.0` is not out yet. Check the tree for what exists; never import or claim a package that is not there.

## How work runs

1. The work is the user's request, or the first row of `docs/roadmap/02-steps.md`.
2. Build the complete feature with its tests: every behavior, option, limit, error and edge case the owning documents define for the current milestone. Never a minimal, partial or stand-in version, even when the complete design is complex. Fix a bug at its root cause, for every path and input it affects, never with a narrow patch or workaround. Every requirement and every bug gets a named test case that fails without the change. No review, verification, audit or mutation passes, and no plan files.
3. Finish all the requested work first. Then run the gates once, fix every failure and rerun until they pass. Never run the gates per step or per file.
4. Delete each finished row from `docs/roadmap/02-steps.md`. If the work changed the design, rewrite the owning document's text so it states the design as it is now.
5. When the docs do not define something (a YAML field, CLI noun or verb, Policy type, `RZ` code, library, limit or trade-off), ask the owner and write the answer into the owning document. Never invent one. Where a step could do more than its documents define, propose the addition to the owner instead of leaving it out, and recommend the fuller option.
6. Commit only when asked.

## Gates

From Git Bash, after all work is done:

```bash
make hygiene lint generate build test supply-chain
make floor FLOOR_GOTOOLCHAIN=go1.26.8
```

Add `make integration` when integration-tagged tests changed. Without make: `go run ./internal/tool/repocheck`, `go generate ./...` with no diff, `go build ./...`, `go vet ./...`, `CGO_ENABLED=0 go test -shuffle=on ./...`, `go mod verify`, `go run ./internal/tool/depgate`. Say which gates could not run and why. `make generate` fails until regenerated files are staged.

## Hard rules (CI fails otherwise)

- **License header** on every hand-written `.go` file, tests included, then a blank line: `// Copyright <creation year> Revington` and `// SPDX-License-Identifier: Apache-2.0`. repocheck wants the same header in the first 512 bytes of `.proto`, `.ts`, `.tsx`, `.mts` and `.cts` files. Generated files start with `// Code generated by <tool>. DO NOT EDIT.`
- **No-license-check scan.** Text files under `cmd/ internal/ pkg/ sdk/ console/`, comments and tests included, never contain the host `revington.co` (any case) or `licensekey`, `licensefile`, `licenseserver`, `licensetoken`, `entitlement`, `enterpriseedition`, `enterpriseonly`, matched after lower-casing and removing `-`, `_`, spaces and tabs, so prose such as "license key" fails too. `testdata/`, `bin/`, `dist/`, `node_modules/` and dot-directories are skipped; exceptions go in `internal/tool/repocheck/nolicensecheck.allow`.
- **Error codes.** Any `RZ-(CFG|RT|UP|AUTH|RL|PLG|AI|CP|STS)-NNN` in a Go string literal outside `internal/errcode/` is registered in `All()`. Every registered code appears in some doc, and every code a doc names is registered.
- **`cmd/<binary>/main.go`** is the only file there and holds only imports and `func main`; flags and logic live under `internal/`.
- **Imports.** Only the standard library, this module and the modules in the `admitted` list of `.golangci.yml`, tests included (no testify, no go-cmp). A new module needs a tech stack catalog row and an `admitted` entry in the same change. `pkg/` and `api/schema` (non-test) import only the standard library and `pkg/`. No `import "C"`. `internal/gateway` never imports `internal/control`, `internal/controlstore` or `internal/cli`; `internal/control` and `internal/cli` never import `internal/gateway`; only `internal/tool` imports `internal/tool`.
- **Banned:** `log` (use `log/slog` through `internal/telemetry`), the `plugin` package, Lua runtimes, `valyala/fasthttp`, `github.com/google/cel-go` (use `cel.dev/cel-go`), `golang.org/x/net/http2` `Server` and `Transport`, `goccy/go-yaml`, `go.yaml.in/yaml/v4` and `gopkg.in/yaml` (`internal/config/profile` is the YAML parser), `fmt.Print*` outside `internal/cli` (write to an `io.Writer`), `init()`.
- **Suppressions** name the linter and a reason, only where it reports: `//nolint:gosec // reason`.
- **Generated schema.** Never hand-edit `api/schema/ruralz/v1alpha1/*.schema.json`: change `pkg/config/v1alpha1`, run `go generate ./pkg/config/v1alpha1`, commit both.
- **Go 1.26 floor.** The code builds and tests on Go 1.26 with `GOEXPERIMENT=jsonv2`: no standard library API newer than Go 1.26.
- **Tests** pass under `-race -shuffle=on` with cgo and with `CGO_ENABLED=0`, and never depend on wall-clock time, order, randomness or the network. Suites that drive a built `ruralzd` meet the clock rule through the controllable-clock test build (`ruralz_testclock`); `docs/engineering/03-testing-and-quality-strategy.md` "Hermetic rule scope" names the suites that measure real time. `internal/cli`, `internal/buildinfo` and `pkg/` tests also run on Windows and macOS.
- **No mutable package-level variables**, except sentinel errors, `go:embed` variables, the linker-set `internal/buildinfo` variables, tests and generated code.
- **Line endings** are LF everywhere.

## Commits

- Every commit carries `Signed-off-by: <author name> <author email>` equal to the commit author (`git commit -s`).
- Title `<type>(<scope>)!: <subject>`, matching `^([a-z]+)(?:\(([a-z0-9][a-z0-9-]*)\))?(!)?: (.+)$`: imperative mood, lower-case first word, no trailing period. Omit the scope when a change spans several; a breaking change adds `!` and a `BREAKING CHANGE:` footer.

| Type | Scopes |
|---|---|
| `feat`, `fix`, `perf`, `refactor` | `gateway`, `control`, `cli`, `config`, `filter`, `plugin`, `ai`, `statestore`, `controlstream`, `console`, `sdk`, `api`, `deploy` |
| `test` | The scopes above, `e2e`, `conformance` |
| `docs` | A document slug: the file name under `docs/` without numeric prefix and `.md`, such as `data-plane` |
| `build`, `ci` | `deps`, `tools`, `workflows` (changes to `internal/tool` are `build(tools)`) |
| `chore`, `revert` | Any; changes to `AGENTS.md`, `CLAUDE.md` and `.claude/` use `chore:` |

## Names

Use the names of `docs/_meta/foundation-pack.md` sections 2, 3 and 11 verbatim: Ruralz Gateway (`ruralzd`), Ruralz Control (`ruralz-control`), Ruralz Console, CLI `ruralz`, Bundle, Revision, Rollout, Node, Cluster, State Store, Control Stream, and the kinds `Route`, `Upstream`, `Policy`, `Plugin`. Never `RuralZ`, `ruralzctl` or `rz`. apiVersion `ruralz/v1alpha1`; errors `RZ-<AREA>-<NNN>`; env vars `RURALZ_*`; metrics `ruralz_<component>_<name>_<unit>`. No `TODO` or `TBD`. Code comments state the rule they implement and cite only `docs/`, never plan or review IDs.
